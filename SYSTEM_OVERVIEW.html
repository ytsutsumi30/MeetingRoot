1. 何をするシステムか

会議室に置いたAndroid端末が、人数情報と録音音声をローカルPC上の TestDashboard に送ります。TestDashboardは音声を Azure Speech で文字起こしし、Claude で議事録を作り、MarkdownとWord(DOCX)として保存します。GitHub Pagesの公開ダッシュボードでは、会議室の人数と生成済み議事録の件数を確認できます。

3. 主な処理フロー

3.1 Android録音から議事録生成まで

Androidが会議音声を録音し、job_id付きで/ingest/recordingへ送信。
TestDashboardが録音を受け取り、ジョブとして保存。重複送信は既存ジョブとして扱う。
音声ファイルをAzure Blobまたはローカル公開URLに置き、Azure Speechが取得できる状態にする。
Azure Speechが音声を文字起こしし、発話単位のtranscript segmentsを返す。
Claudeがtranscriptを読み、会議サマリ・議題・決定事項・アクションアイテムをMarkdown化。
Markdown末尾に「文字起こし全文」を追記し、DOCXも生成。GitHub Pagesは/api/jobsから件数を表示。
